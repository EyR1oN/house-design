# Репозиторій і робота з двох ноутбуків

Ця папка підготовлена як окремий Git-репозиторій для GitHub із Git LFS. Початковий переносний ZIP і попередня локальна редакція збережені окремо. Для щоденної роботи дивіться README.md; розділ початкового git init нижче є довідкою для нового імпорту, а не командою для повторного запуску.

Моделі .blend, GLB, текстури/фото та великий автономний House_Viewer.html налаштовано для Git LFS. HTML близько 332 МБ теж потрібно зберігати через LFS, хоча це текстовий файл. Інакше він роздуватиме звичайну історію або буде відхилений сервером.

Встановіть Git і Git LFS з офіційних джерел. На Windows Git LFS часто входить до Git for Windows, однак перевірте `git lfs version`.

```powershell
git init -b main
git lfs install
git add .gitattributes .gitignore
git add .
git lfs ls-files
git status
git commit -m "Import house design revision 16"
```

Далі створіть свій віддалений репозиторій і прив'яжіть його URL через `git remote add origin <URL>`, потім `git push -u origin main`. Перед вибором сервера перевірте підтримку LFS, ліміти місця/трафіку та максимального розміру LFS-файла: master близько 381 МБ. Для особистого проєкту з бібліотечними активами використовуйте приватний доступ; кредити й умови використання є в ASSET_CREDITS.md.

На другому ноутбуці спочатку встановіть Git LFS, потім:

```powershell
git clone <URL>
cd <папка-репозиторію>
git lfs install
git lfs pull
```

Перед роботою на будь-якому ноутбуці:

```powershell
git status
git pull --ff-only
git lfs pull
```

Якщо є незбережені/незакомічені зміни — спочатку розберіться з ними, не робіть примусового скидання. Після роботи збережіть Blender, закрийте його, синхронізуйте дані/GLB/HTML/потрібні рендери й хендоф, перевірте зміни, потім:

```powershell
git add .
git commit -m "Describe the house update"
git push
```

Git переносить файли, але сам не оновлює HTML після зміни .blend. Обидва ноутбуки можуть переглядати проєкт одночасно; одночасне редагування одного .blend не має автоматичного злиття. Не вирішуйте двійковий конфлікт навмання — збережіть обидві версії під окремими назвами.

Tools/, резервні папки, ZIP, журнали, .blend1 і одноразові TRANSFER_INFO/ не включаються в коміти. В архіві вони присутні, якщо потрібні для перенесення. Після clone на новій машині знадобиться свій Blender 4.5.3 або папка Tools/ з цього ZIP; копія Blender не їздить в кожному Git-коміті.

Джерела: https://git-lfs.com/ та https://git-scm.com/docs/gitattributes . Підготовлені атрибути діють до першого додавання великих файлів; вже створену звичайну Git-історію вони заднім числом не перетворюють.
